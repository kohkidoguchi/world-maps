# 世界研究マップ (Research Map)

過去半年の全分野の論文のうち「重要論文」（分野・出版年内で被引用上位 1%、または FWCI ≥ 10）だけを、
OpenAlex のトピック階層（4 ドメイン → 26 分野 → 252 サブ分野 → 4,516 トピック）の上に配置し、
毎日「同じ基準を超えた新しい論文」を追加していくダッシュボード。

```
research_map/
  build.py          重要論文マップ: --init（初回・半年分） / --update（日次） / --rebuild / --dev-from-raw
  build_weekly.py   旧版（週の全新着論文を事前スコアで採点）。HTTP・トピック・リンク計算の共通コードもここ
  serve.py          ローカル配信 (http://localhost:8766)
  run_daily.bat     python build.py（状態が空なら --init、あれば --update）
  data/map/         papers.json = 採用済み論文の状態（参考文献リスト込み）、runs.jsonl = 実行ログ
  data/raw/         旧版の日別生データ（--dev-from-raw の材料）
  data/entities/    トピック階層、（旧版の）掲載誌・機関キャッシュ
  data/snapshots/   日次スナップショット（トピック別 n / 重み / 勢い）
  web/              D3 フロントエンド
```

## 実行

```
pip install -r requirements.txt
python build.py --init --months 6   # 初回: 分野×月ごとに被引用上位を取得し、基準を超えた論文を採用（約 200 リクエスト）
python build.py --update            # 日次: 直近3週間の分野別上位を見て追加、90日以内の論文の被引用数を更新（約 100〜150）
python build.py --rebuild           # ネットワークなしで data.json を再生成（採点式・画面の調整用）
python serve.py                     # → http://localhost:8766
```

## 採点と採用（重要論文モード）

- **採用基準**: OpenAlex の `citation_normalized_percentile.is_in_top_1_percent`（分野・出版年内の上位 1%）または FWCI ≥ 10、
  かつ被引用 5 以上・参考文献あり・撤回なし。被引用 20,000 超は不良データとして除外。
- **スコア** = 20·log2(1 + FWCI) + log10(1 + 被引用)、上限 100。FWCI は分野・出版年で正規化した被引用指標（1.0 = 世界平均）なので
  分野をまたいで比べられる。被引用の生値は同点の順位付けにだけ効く。
- **勢い** = log2(直近 2 ヶ月の重要論文に占めるトピックの構成比 ÷ それ以前の構成比)。若い論文ほど被引用が蓄積していないため
  採用数が少ないが、構成比にすることで全体の少なさは打ち消される。
- **線** = 同じ文献を引用（書誌結合、共有 2 本以上、コサイン）・直接引用・著者が共通。参考文献リストは一覧取得に含めるので追加リクエストなし。

旧版（週の全新着を著者・掲載誌・機関の実績から推定採点）の設計は `build_weekly.py` の docstring と下記に残す。

## OpenAlex の無料枠（重要）

- **1 日 1,000 リクエスト（$0.10 相当、1 リクエスト $0.0001）。UTC 0 時 = 日本時間 9:00 にリセット。**
  超えると 429 "Insufficient budget"。前払いで増やせる（openalex.org/pricing）。
- 必要リクエスト数の目安: 7 日分の初回構築 ≒ 1,300（論文ページ 700・掲載誌 155・機関 300・著者 300・参考文献 260）、
  日次の差分 ≒ 300。初回だけ 2 日に分けるか、$1 程度の前払いで賄う。
- `build.py` は予算切れを検知すると、取得済み分をキャッシュに保存して残りで構築し、
  末尾に `INCOMPLETE - entities still to fetch` と残件数を出す。翌日もう一度実行すれば続きから埋まる。
  取得は「登場回数の多い ID から」なので、途中で切れても主要な掲載誌・機関は先に埋まる。
- `--offline` でネットワークなしに再構築できる（採点式や画面の調整用）。

## データと設計判断

- **ソースは OpenAlex のみ**（無料枠、`mailto` 付きポライトプール）。BCG プロキシ越しでは `truststore` が必要。
- **対象タイプ** は article / preprint / review（dataset・software・paratext などを除外。paratext は雑誌の目次で被引用が異常に大きく、生の cited_by_count 順を汚染する）。
- **取り込み遅延**: OpenAlex は publication_date の当日〜翌日には数%しか載らないため、終了日は「一昨日」がデフォルト。`from_created_date` フィルタは有料プラン限定なので使わない。
- **月初集中**: 雑誌の号日付により毎月 1 日に 2〜3 倍の論文が集中する。基準期間（8 週）に含めて平均化しているが、対象週に月初が入ると全体的に勢いが上振れする。

## 採点（期待インパクト）

新着論文には引用がないので、被引用数そのものではなく「引用されるであろう度合い」を推定する。

| 成分 | 中身 | 重み |
|---|---|---|
| 掲載誌 | log(2 年平均被引用) の分野内パーセンタイル | 0.32 |
| 所属機関 | 著者所属機関の最大値、同上 | 0.15 |
| 著者 | 著者陣の最大 h 指数と最大 2 年平均被引用、同上（ショートリストのみ） | 0.33 |
| メタデータ品質 | 参考文献あり／所属あり／掲載誌あり／複数著者 | 0.10 |
| 初期引用 | log(被引用) と FWCI | 0.10 |

- 著者の実績は全件取れない（数十万人）ので、掲載誌＋機関の事前スコアで **分野ごとに上位 160 件＋既に引用のある論文** をショートリスト（上限 5,000）し、その著者だけ取得する。
- ショートリスト外の論文は掲載誌＋機関のみで採点し、0.85 倍に抑える（著者情報のない論文が上位に来ないようにするため）。
- パーセンタイルは **分野内** で取る。数学と医学では被引用の桁が違うので、分野を跨いだ生の比較はしない。

## 勢い（momentum）

`log2( 今週のトピック構成比 / 基準 8 週のトピック構成比 )`。絶対数ではなく構成比を使うのは、取り込み遅延で直近週の総数が常に小さいため。+1 で「通常の 2 倍の比率」、−1 で半分。
